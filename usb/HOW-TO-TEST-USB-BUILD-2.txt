LINELEDGER USB BUILD 2 - WHAT CHANGED AND HOW TO TEST IT

For Moshe. About 20 minutes of your time, most of it waiting.

You need: the Windows PC, the USB stick, and a few minutes
where you can leave the PC alone.


-------------------------------------------------------------
WHAT THIS BUILD IS TRYING TO FIX
-------------------------------------------------------------

Two things you reported.

One: unzipping onto the stick took more than half an hour.

Two: the app was slow, and "Create organization" ended in a
bare 500 Server Error.

You said it might be because the folder has over 15,000
individual files. You were right - that is exactly it, and it
turned out to be behind both problems.


-------------------------------------------------------------
WHAT WAS ACTUALLY WRONG
-------------------------------------------------------------

Windows writes files to a USB stick one at a time, and each
one costs about the same no matter how small it is. Fifteen
thousand small files is therefore fifteen thousand separate
slow operations. That is your half hour.

The same folder was also being re-read on every single page
you opened, because a setting that keeps the code in memory
had been deliberately switched OFF in the first build. The
reasoning behind switching it off was simply wrong.

So: too many files, and them being read over and over.


-------------------------------------------------------------
WHAT IS DIFFERENT NOW
-------------------------------------------------------------

1. There are fewer files. About 17,200 went down to 13,304.
Nothing that runs was removed - the build now starts the app
up afterwards and fails on purpose if anything needed went
missing.

2. The download is no longer thousands of loose files. The
whole application travels as ONE packed file. The download now
has about a hundred things in it instead of seventeen
thousand, and Windows mostly just has to copy one big file to
the stick - which it is fast at.

That is the change that should turn your half hour into a
couple of minutes. The file count matters, but this matters
more.

3. LineLedger unpacks itself, once, the first time you start
it - using a tool built into Windows that is far quicker at
this than the unzip window is.

4. The code now stays in memory while LineLedger is running
instead of being re-read off the stick for every page. On a
test machine this alone made pages about twice as fast, and on
a slow stick the difference should be much bigger.

5. The screens are prepared once, on first start, instead of
each one being prepared the first time you happen to open it.

6. When something does go wrong, you can now see WHY. There is
a new "Show the error log.bat" - more on that below.


-------------------------------------------------------------
TESTING IT
-------------------------------------------------------------

1. Delete the old LineLedger folder from the stick.

Your books are in the Data folder. If you entered anything you
want to keep, copy Data somewhere safe first. If you have not
entered anything real yet, just delete the lot.


2. On GitHub, go to Actions, then "Build USB bundle", then
"Run workflow".

Give it a tag such as usb-2026-08-26. It takes several
minutes. When it finishes there is a new Release with a .zip
in it.


3. Download the .zip and unzip it onto the stick, with the
LineLedger folder at the top level of the stick.

This is the step that took you over half an hour. Time it
roughly. It should now be a couple of minutes.

If it is still slow here, stop and tell me - that would mean
the cause is something other than the file count, and I would
be wrong about the whole diagnosis.


4. Double-click "Start LineLedger.bat" and then leave it
alone.

The first start unpacks the program and prepares the screens.
It will sit there looking like nothing is happening, possibly
for several minutes. That is expected, and it only ever
happens once.

Do not unplug the stick during this. Do not close the black
window.


5. When LineLedger opens, sign up and go through the setup
wizard exactly as you did last time - Gitty Roth Daycare,
Canada CAD, Sole proprietorship, Minimal 7 accounts.

Click "Create organization".


6. Tell me what happened, either way.

IF IT WORKED: say so, and say roughly how long the unzip took,
how long the first start took, and whether the app feels
quicker to move around in.

IF YOU STILL GET 500 Server Error: this is the important part.
Go back to the LineLedger folder on the stick and double-click

    Show the error log.bat

Notepad opens with the log. Scroll to the very BOTTOM. The
last few lines are the actual reason it failed.

Send me those last lines - a screenshot is fine. That log is
the thing that has been missing, and with it the problem is
usually fixable outright rather than guessed at.


-------------------------------------------------------------
ONE THING I COULD NOT DO
-------------------------------------------------------------

I could not reproduce your 500 error. Not on Linux, not with
your exact wizard answers, not twice over.

So I have not "fixed the 500". What this build does is remove
the most likely cause of it, and make sure that if it happens
again it tells you why instead of showing you six characters.

That is why step 6 matters more than the rest.
